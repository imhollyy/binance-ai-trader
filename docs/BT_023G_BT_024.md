# BT-023G and BT-024 research implementation

## BT-023G

`ai_trainable_model.py` implements deterministic full-batch multinomial
logistic regression with SELL/HOLD/BUY labels. It is trainable and
explainable through its fixed features and coefficients; it is not a rules
engine. Features combine closed 1m, 5m and 15m OHLCV trend, volume,
volatility and momentum with the repository's multi-timeframe regime
classifier. Missing, stale, unclosed, misaligned or uncertain-regime input
fails as NO_TRADE. Artifacts and manifests are canonical JSON with SHA-256
checks; normalization is fitted only on the training partition and the split
enforces label maturity before test begins.

Prediction probabilities are explicitly uncalibrated, the adapter has no
database, exchange, account or order imports, and every prediction must be
handed to an independent receipt recorder before the adapter returns. The
existing immutable forecast receipt implementation remains disposable
PostgreSQL test infrastructure; it is not yet a general research service.
No production model was fit from the checked-in research files: those contain
four isolated 5m single-day windows and do not provide aligned 1m/15m input or
prospective prediction receipts. Therefore no model training/test dates,
accuracy, calibration, or positive edge are claimed by this change.

## BT-024

`risk_guard.py` is a pure deterministic gate. Its versioned 1–5 profile
requires explicit critical limits and never obtains them from the AI. Hard
user caps are always applied. Stale settings, daily loss, drawdown, loss
streak, position/capital/risk bounds, missing stops, or unverifiable costs
reject new risk. The audit wrapper synchronously hands each decision to an
independent recorder. PAUSED/STOPPED reject new risk and identify undefined
protection behavior; EMERGENCY_FLATTEN is not described as a successful close
without a tested closure engine. No order path is connected.

The existing versioned bot state transition service remains the source for
state transitions. This module gates proposals only; persistence, atomic
multi-process risk reservations, an audit database writer, and a tested
closure engine are not supplied here. It must remain shadow/research-only
until those integrations and their restart/concurrency tests exist.
